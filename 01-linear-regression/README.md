# 01 · Linear Regression from scratch

Linear regression with **NumPy only** (z-score scaling + vectorized batch gradient descent), trained on California Housing and verified against scikit-learn. The aim is not a record-breaking model, it is to show I understand every line that trains one: the cost, its gradients, why feature scaling matters, and when the learning rate breaks training.

## Problem

Predict the median house value of a California block group (in units of $100k) from 8 features: median income, house age, average rooms, average bedrooms, population, average occupancy, latitude and longitude.

## Data

`sklearn.datasets.fetch_california_housing`: 20,640 rows from the 1990 US census (Pace & Barry, 1997). It is downloaded on first run and not stored in this repo. The target is capped at 5.0 ($500k), which matters later.

## Method

- **Split:** 80/20 train/test, `random_state=42`.
- **Scaling:** z-score, with mean and std computed on the **train set only**, then applied to both sets (no leakage).
- **Model:** `ŷ = Xw + b`
- **Cost:** `J(w, b) = 1/(2m) · Σ (ŷ − y)²`
- **Optimizer:** batch gradient descent, fully vectorized, with a simultaneous update:
  `w ← w − α · Xᵀ(ŷ − y) / m`, `b ← b − α · mean(ŷ − y)`
- **Checks:** weights and test RMSE compared against `sklearn.linear_model.LinearRegression`; the analytic gradients are tested against finite differences; the largest stable learning rate is derived as `2/λmax` and tested.

## What I learned

- **Learning rate.** 0.001 is far too slow: after 1,000 iterations the cost is still 0.656, against 0.259 at the optimum. 0.01 is close but not there (0.274). 0.1 and 0.5 reach the same minimum within a few hundred iterations. The right panel of the first figure shows the other side: just above `lr = 2/λmax` (λmax is the largest eigenvalue of `XᵀX/m`) the cost grows instead of shrinking, while just below it the cost falls.
- **Scaling.** Scaling changes the shape of the cost surface, not the model. The conditioning table shows the condition number and the largest stable learning rate for raw versus standardized features: with raw features one learning rate cannot suit both population (thousands) and median income (single digits).
- **Matching scikit-learn.** Test RMSE agrees to four decimals, but the weights still differ by up to 2.7e-3 after 1,000 iterations, mostly on Latitude and Longitude. Those features are strongly correlated, which makes the cost valley long and narrow, so gradient descent crawls along it. The iteration table shows the gap closing as I give it more iterations.
- **Where a linear model stops.** R² is about 0.58, well above the predict-the-mean baseline but far from perfect. In the predicted-vs-actual plot, the true values pile up at the 5.0 cap, which a straight line cannot represent, and the spread of errors grows for expensive districts.

## Limitations and next steps

- Latitude and longitude enter as straight lines, so the model cannot learn that "near the coast" is expensive. Next: interaction and polynomial features, then a tree-based model as an upper reference.
- The capped target (5.0) biases the fit at the high end. Next: report the metrics with and without the capped rows.
- Test RMSE is a single split. Next: k-fold cross-validation to see how much it varies.
